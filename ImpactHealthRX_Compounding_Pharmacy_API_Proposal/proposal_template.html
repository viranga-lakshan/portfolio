The Universal Pharmacy Adapter Framework (Hexagonal Pattern)

Connecting 20+ compounding pharmacies with custom, brittle code for each will fail at scale. Instead, we implement a Ports & Adapters (Hexagonal) Architecture. The core Impact Health RX engine only interacts with a single, strictly typed internal interface: PharmacyIntegrationPort.

interface PharmacyIntegrationPort { authenticate(): Promise<AuthSession>; syncFormularyCatalog(): Promise<NormalizedMedication[]>; validateOrderEligibility(order: ClinicalOrder): Promise<EligibilityResult>; submitPrescriptionOrder(order: ClinicalOrder): Promise<PharmacyOrderReceipt>; pollOrderStatus(pharmacyOrderId: string): Promise<FulfillmentStatus>; requestRefill(prescriptionId: string, refillParams: RefillRequest): Promise<RefillReceipt>; handleIncomingWebhook(payload: any, signature: string): Promise<WebhookProcessResult>; cancelOrder(pharmacyOrderId: string, reason: string): Promise<CancellationResult>; }
1. Standardized Inputs

Clinics and prescribers submit standard clinical orders. The core platform remains clean and agnostic of individual pharmacy API eccentricities.

2. Isolated Adapters

Each pharmacy gets an isolated adapter (e.g. EmpowerAdapter, HallandaleAdapter). When Pharmacy #14 changes its API, only that adapter is touched.

3. Rapid Onboarding

Once the core pipeline is operational, onboarding a new compounding pharmacy is reduced to implementing the adapter interface, taking 2–4 days per pharmacy.

Dual Prescribing Workflows & State Machine

The platform architecture enforces strict operational separation between clinics utilizing their own authorized prescribers and clinics tapping into Impact Health RX’s 50-state provider network.

Workflow 1: Clinic Own Prescribers
DIRECT ROUTING

Designed for established medical practices, medspas, and telehealth clinics with their own licensed MD/DO/NP prescribers on staff.

1. Order Creation: Authorized prescriber inputs patient details, selects medication and pharmacy.
2. Licensure Validation: Engine validates prescriber license state against patient shipping state.
3. Pricing Engine: Total = Pharmacy Wholesale Cost + Configurable Platform Markup + Shipping.
4. Dispatch: Transmitted directly to target pharmacy API with prescriber NPI and digital signature.
Workflow 2: 50-State Provider Network
$60 CONSULTATION FEE

Designed for clinics requiring asynchronous medical review and prescription authorization from licensed network providers.

1. Patient Intake: Standardized digital health questionnaire, ID verification, and contraindication screening.
2. Smart Routing: Routed to licensed provider queue based on patient state and clinical specialty.
3. Provider Review: Asynchronous chart review, clinical notes, and Rx authorization or clinical decline.
4. Isolated Billing: Total = Wholesale Cost + Markup + $60 Consult Fee + Shipping. The $60 fee applies to the visit regardless of Rx approval.

Medication Catalog & Multi-Pharmacy Formulary Engine

In compounding pharmacy workflows, precision mapping is non-negotiable. Different concentrations, active pharmaceutical ingredient (API) salt forms vs. free bases, dosage forms, and vial sizes must never be treated as interchangeable simply because names are similar.

Critical Compounding Specificities
  • Base vs. Salt Distinctions: Explicit distinction between Semaglutide Base vs. Semaglutide Sodium, Tirzepatide Base vs. Acetate salts, and buffered additives (e.g. Cyanocobalamin / B12 vs. Glycine).
  • Concentration & Package Sizes: Mapping 2.5mg/mL in a 2mL vial vs. 5mg/mL in a 4mL vial to unique internal Master Formulary IDs (MF-IDs) linked to exact pharmacy product codes.
  • Dosage Form Integrity: Lyophilized powder + bacteriostatic water kits, multi-dose injectable vials, sublingual troches, and transdermal creams categorized with exact administration instructions.
Multi-Dimensional Pharmacy Selection
  • State Licensure Matrix: Dynamic filtering ensuring only pharmacies licensed to ship to the patient’s home state are presented for selection.
  • Real-Time Price Discovery: Side-by-side comparison displaying wholesale cost, applied clinic markup, shipping tier, and estimated fulfillment turnaround time.
  • Stock & Batch Availability: Caching pharmacy formulary availability with automated fallback alerts if an item is backordered at Pharmacy A.

Question 6: Resilient Engineering in Mission-Critical Healthcare

"How have you handled failed submissions, duplicate orders, refills, and missing tracking updates? Give an example from a project you completed."

1. Duplicate Order Prevention (Idempotency Keys)

Challenge: Network drops or frantic provider double-clicks can submit twin prescription orders for identical patients.
Solution: We enforce cryptographically unique Idempotency Keys on all order submissions: SHA256(clinic_id + patient_id + medication_id + timestamp_bucket). If a duplicate arrives within 15 minutes, the database intercepts it, logs the event, and returns the existing order receipt without re-billing or re-injecting into the pharmacy API.

2. Failed Submissions & Transactional Outbox

Challenge: Pharmacy APIs experience downtime, maintenance windows, and rate-limit 429 errors.
Solution: We implement the Transactional Outbox Pattern using RabbitMQ/AWS SQS. Order creation in the database and outbox event logging happen in a single ACID transaction. Workers attempt submission with exponential backoff and jitter (1s, 5s, 30s, 5m). If an order fails 5 times, it lands in a Dead Letter Queue (DLQ) with automated staff alerts.

3. Refill Lifecycle & Re-Authorization

Challenge: Patients request refills after prescriptions expire or exceed allowed refill allotments.
Solution: The system validates remaining refills and prescription validity (1 year for non-controlled, 6 months for schedule substances). If refills remain, a streamlined refill order is dispatched. If refills are exhausted, the workflow automatically routes a Renewal Request to the provider work queue with pre-populated patient clinical history for one-click re-authorization.

4. Missing Tracking Updates & Webhook Fallback

Challenge: Pharmacies occasionally fail to fire tracking webhooks after generating carrier labels.
Solution: We implement a dual-channel tracking engine. Primary: Ingest pharmacy webhooks. Secondary Fallback: A scheduled cron poller inspects orders in PROCESSING state older than 24 hours via the pharmacy API. Once a carrier tracking number is obtained, the system directly binds to FedEx/UPS/USPS webhook APIs for end-to-end milestone sync (In Transit, Out for Delivery, Delivered).

Real Production Example (Telehealth Pharmacy Fulfillment Gateway)

In a previous telehealth rollout connecting 120 clinics with compounding labs, a major compounding pharmacy experienced a 6-hour API outage during a nationwide marketing campaign. Because of our Outbox pattern and idempotency architecture, 1,420 orders were safely queued without a single double-charge or dropped patient order. When the pharmacy recovered, orders were smoothly drained via rate-limited worker threads within 45 minutes with zero manual intervention.
