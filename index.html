Holsten Arabia — Umbraco CMS Implementation

Visit Live Site ↗

Holsten is a globally recognised beverage brand. This is the Umbraco CMS implementation for its Arabia-region website, where I handle the CMS build — content structure, Document Types, Block List/Block Grid, templating, forms, and multilingual content.

1.1 Content Structure

Tree Architecture

The content tree reflects how the site is organised in practice — Home, News, TopNavigation, Footer, ContactBanner, Privacy Policies, FAQs, Venue Listing, Enquiries/forms pages, Terms & Conditions, Cookies handling, and SEO settings, each managed as an independent node.

1.2 Document Type Library

Reusable Element Types

Page types such as FAQs, News, and Home sit alongside composition/element types like FAQCard, FlavoursCardGrid, HeroBanner, and NewsCardGrid — the building blocks used inside Block List and Block Grid properties.

1.3 Block List & Block Grid

Modular Editor UI

Block List Property Editor configuration for the Home page's "sections" property — StoreCardGrid, FlavoursCardGrid, NewsCardGrid, VenuesCardGrid, FAQCard, and HeroBanner are registered, letting content editors add and reorder blocks dynamically.

1.4 Templating (Razor Views)

Home.cshtml Pipeline

Pulls shared content (TopNavigation, ContactBanner, Footer) from the root, reads the Block List model, handles culture/RTL logic for Arabic, resolves media crops for favicon/OG images, and prepares SEO metadata working directly against Umbraco content models.

1.5 Umbraco Forms

Bilingual Enquiries

Forms such as the Business Enquiry form are built and maintained through Umbraco Forms, including field-level validation, custom workflows, and separate Arabic and English variants to serve the region's diverse audience.

1.6 Multilingual (EN / AR)

RTL & Language Switching

Fully bilingual setup with separate English and Arabic variants per node. Editors switch languages directly inside the Content Editor, maintaining distinct Block List sections that support right-to-left Arabic layouts on the frontend.

Al Ain Museum & NHMAD — Sitecore Headless Architecture

Visit Live Al Ain Museum ↗ · Visit Live NHMAD ↗

Al Ain Museum (UAE Government project) and Natural History Museum Abu Dhabi are built on a headless Sitecore + Next.js architecture. I work on the Sitecore backend — content structure, templates, renderings, GraphQL and Layout Service integration, and multilingual content.

2.1 Content Tree Overview

V1 & V2 Root Isolation

Both live Version 1 (alain-site-core-nextjs) and in-development Version 2 sit under the same Content root, each with its own home node, Components, Content, Data, and Dictionary items cleanly isolated.

2.2 Page Structure

Next.js Route Mapping

Each public page is represented as its own item under the home node (Privacy, Cookie policy, FAQs, Contact Us, Exhibitions & Events, The Museum) mapping directly to routing on the Next.js frontend.

2.3 Reusable Components

Datasource Architecture

Shared components (Navigation, Footer, TopNavigation, ContentBlock) are stored in dedicated Datasource folders, reused across multiple pages without content duplication.

2.4 Renderings & Templates

Sitecore Helix Principles

Renderings and Templates strictly follow Sitecore's Foundation/Feature convention. Built and maintained item templates behind banners, columns, contact forms, FAQs, galleries, and sliders.

2.5 Version 1: GraphQL

Nested Children Queries

Sections like CollectionHighlights hold SlideItem children. Version 1 resolves this through native Sitecore GraphQL using inline fragments on SlideItem to pull fields in a single query.

2.6 Version 2: Layout Service

No Extra GraphQL Round-Trip

Version 2 resolves nested children directly through the Layout Service response via a custom RenderingContentsResolver, eliminating the extra request. Managed via Sitecore config patches.
